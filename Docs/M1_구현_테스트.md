# M1 파티·원소 구현 및 테스트

기획서 03의 파티·스위칭 및 원소 반응표, 05의 M1을 구현했습니다. Unity 6000.6.0f1 / URP 17.6.0 / Cinemachine 6.6.0 / Input System 1.20.0의 기존 M0 구성을 사용합니다. 기획서와 M0 씬·입력·애니메이션 리소스는 보존했습니다.

## 실행할 씬

Unity Hub에서 `D:\Project\ORBIS`를 6000.6.0f1로 열고 임포트·컴파일을 기다립니다. **Orbis > M1 > Setup and Validate** 후 아래 메뉴에서 씬을 열고 **Play**, Game 뷰 클릭으로 시작합니다. Scene 뷰에서는 런타임 테스트 공간이 생성되지 않으며 Play 시 M0 공간과 M1 파티·타깃이 생성됩니다.

| 메뉴 / 씬 | 1 | 2 | 3 | 4 |
|---|---|---|---|---|
| Open Party Prototype / `Assets/Orbis/M1/Scenes/M1_PartyPrototype.unity` | 이그니스 / 화 | 마리스 / 수 | 스파클 / 뢰 | 아우라 / 풍 |
| Open Crystallize Prototype / `Assets/Orbis/M1/Scenes/M1_CrystallizePrototype.unity` | 이그니스 / 화 | 마리스 / 수 | 스파클 / 뢰 | 그롬 / 암 |

네 멤버는 각각 원소 정체성·부착·보호막·누적 피해 상태를 가집니다. 필드에서는 활성 멤버 하나를 M0의 공용 임시 아바타와 색상으로 표시합니다. 캐릭터별 활·창·쌍검·대검 동작과 고유 스킬은 이번 M1에서 만들지 않았습니다.

## 조작

| 입력 | 동작 |
|---|---|
| WASD / Shift / Space | 카메라 기준 이동 / 달리기 / 지상 점프 |
| 마우스 / 왼쪽 클릭 | 카메라 회전 / 지상 3단 기본공격 |
| 키보드 상단 1~4 | 해당 슬롯으로 즉시 전환 |
| Esc / 해제 후 왼쪽 클릭 | 입력 중단 / 입력 재개; 재개 클릭은 공격으로 처리하지 않음 |
| R | 파티 1번, 플레이어 시작 위치, 적 위치·부착·피해, 전원 보호막·감전·전환 제한 초기화 |
| F6 | 세 타깃의 위치·부착·감전·누적 피해·피격 횟수 초기화 |
| F7 | 활성 캐릭터에게 수 원소 10 피해를 가하는 테스트 입력 |
| F8 | 원소 폭발 후 1초 전환 제한 연결 함수 테스트; 실제 폭발 스킬은 시전하지 않음 |
| F9 | 세 타깃을 초기화하고 앞의 주 타깃에 풍 원소 4초를 부착하는 테스트 입력 |

M0의 게임패드 이동·카메라·점프·공격도 유지됩니다. M1 슬롯 전환과 F6~F9 검증 입력은 키보드입니다. 숫자를 계속 누르는 동안 반복 전환하지 않으며, 여러 슬롯을 같은 프레임에 누르면 가장 작은 번호를 처리합니다.

왼쪽 HUD는 활성 슬롯, 각 멤버와 세 타깃의 `Aura`(원소/남은 초/부착 소스), `Shield`, `Damage`(실드가 흡수하고 남은 누적 피해)를 표시합니다. 우측에는 최근 원소 이벤트가 표시되고, 반응은 Console에도 기록됩니다. 타깃 몸 색은 현재 부착 원소를 나타내며 만료·소비 시 원래 색으로 돌아갑니다.

## 반응별 수동 테스트

각 행을 시작하기 전에 `R`로 초기화합니다. **공격은 한 번 클릭하고 앞 타깃의 색 또는 Aura가 바뀌는 명중 시점까지 약 0.2초 기다립니다.** 이후 전환하면 이전 공격이 취소되어 새 캐릭터의 공격을 바로 시작할 수 있습니다.

| 확인 항목 | 씬 / 입력 순서 | 기대 결과 |
|---|---|---|
| 증발 | Party: `1 → 공격 → 2 → 공격` | `Vaporize`, 두 번째 피해 20, 주 타깃 누적 30, 원소 소비 |
| 역방향 증발 | Party: `2 → 공격 → 1 → 공격` | 두 번째 피해 15, 주 타깃 누적 25 |
| 감전 | Party: `2 → 공격 → 3 → 공격`, 3초 대기 | `ElectroCharged`, 주 타깃에 1초마다 4씩 3회, 양옆에 2씩 3회 연쇄; 누적 주 타깃 32 / 이웃 각각 6 |
| 과부하 | Party: `1 → 공격 → 3 → 공격` | `Overload`, 주 타깃 누적 28 / 이웃 각각 8, 세 타깃 넉백. 다음 테스트 전 R 또는 F6으로 위치 복귀 |
| 확산 | Party: `1 → 공격 → 4 → 공격` | `Swirl`, 주 타깃의 화 소비, 양옆 타깃에 화 4초 및 각각 5 피해 |
| 결정화 | Crystallize: `1 → 공격 → 4 → 공격` | `Crystallize`, 그롬에게 화 보호막 25 / 6초 장착 |
| 풍+암 우선순위 | Crystallize: `R → 4 → F9 → 공격` | 확정한 결정화 판정, 그롬에게 풍 보호막 장착 |
| 보호막 흡수 | 결정화 직후 `F7` | 수 피해 10을 보호막이 흡수, 실드 25→15, 캐릭터 누적 피해 증가 없음 |

기본공격의 공격 범위 밖에 양옆 타깃을 배치했으므로 최초 타격은 앞 타깃 하나에 맞고, 이웃의 변화는 반응 전파로 발생합니다. 피해 수치는 연속 클릭 없이 위 순서를 한 번 수행했을 때의 값입니다.

## 전환·만료·M0 회귀 확인

1. `1`로 앞 타깃을 공격하고 Aura가 화인 상태에서 `2`를 누릅니다. 타깃의 소스는 Ignis를 유지하고 남은 시간이 4초로 갱신됩니다. 그 안에 수 공격하면 증발합니다. 4초 넘게 기다려 Aura가 none이 된 후 공격하면 수 부착만 발생합니다. 이미 사라지거나 반응으로 소비된 원소는 전환으로 복구되지 않습니다.
2. `F7`로 1번 캐릭터에게 수를 부착하고 `2`로 전환합니다. 비활성 1번 멤버의 수 타이머도 계속 감소합니다. 만료 전에 `1`로 돌아오면 남은 부착이 유지되고, 보호막도 같은 방식으로 멤버별로 유지·만료됩니다.
3. 이동·카메라 회전·점프 중 `1~4`로 전환합니다. 위치, 몸 방향, 카메라 궤도와 점프 흐름이 이어지고 캐릭터가 중복 생성되지 않습니다.
4. 공격 중 방향키·Space로 이동/재점프할 수 없는 M0 정책을 확인합니다. 각 타 시작에서만 입력 방향으로 회전합니다. 콤보를 예약하고 다른 슬롯으로 전환하면 이전 콤보와 예약이 취소됩니다. 새 공격은 1타부터 새 원소를 사용합니다.
5. `F8` 직후 다른 슬롯을 누르면 1초 동안 전환이 거부됩니다. HUD 제한 시간이 0이 된 뒤 다시 누르면 전환됩니다. 차단 중 누른 입력은 예약하지 않습니다. 평소에는 연속 전환에 쿨다운이 없습니다.
6. `Esc`로 입력을 해제한 동안 숫자키가 파티를 바꾸지 않는지 확인합니다. Game 뷰를 클릭해 재개한 클릭으로 공격이 발생하면 안 됩니다.
7. **Orbis > M0 > Open Prototype** 씬에서 걷기·달리기·점프, 벽 충돌, 카메라, 기존 3단 콤보가 그대로 동작하는지도 확인합니다.

## 구현 정책과 기본값

확정한 정책은 **기존 대상에 부착된 원소를 전환 시점부터 4초 유지**, **풍+암은 결정화 우선**입니다. 별도의 원소 장판을 생성하지 않습니다.

| 항목 | 구현값 / 정책 |
|---|---|
| 파티 | 서로 다른 소스 ID와 Actor를 가진 4명, 활성 1명. 공유 아바타가 이동·카메라 연속성 유지 |
| 일반 전환 / 폭발 후 제한 | 쿨다운 없음 / `NotifyBurstUsed()` 호출 후 1초 |
| 전환과 공격 | 전환이 공격 및 예약을 취소. 위치·중력 속도는 유지 |
| 기본 원소 부착 | 타당 10 피해, 단일 태그 4초. 기본공격별 강도 게이지는 도입하지 않음 |
| 동일 원소 재부착 | 시간과 소스를 새 부착으로 갱신. 동일 원소끼리 반응하지 않음 |
| 반응 소비 | 한 번의 반응에서 기존 태그와 들어온 태그 모두 소비. 이후 공격은 새 부착부터 시작 |
| 증발 | 들어온 원소가 수일 때 2배, 화일 때 1.5배 |
| 감전 | 첫 주기 1초 후, 1초 간격 3회. 원피해 40%, 반경 3m 이웃에 원피해 20%. 같은 타깃 재감전은 3회로 갱신 |
| 과부하 | 원피해 80% 추가, 반경 2.5m, 최대 수평 1.5m 넉백. World 충돌을 검사 |
| 확산 | 반경 3m, 이웃에 원피해 50%와 확산한 원소 부착. 이웃의 기존 태그를 교체하며 재귀 반응은 하지 않음 |
| 결정화 | 암 이외의 조합 원소 속성 실드를 시전자에게 즉시 장착. 25 흡수 / 6초. 재획득은 교체, 중첩 없음 |
| 보호막 속성 | 속성 정보는 보관하되 M1에서 속성별 흡수 효율 차이는 없음 |
| 범위 효과 | 반대 팀의 필드 타깃만, World 레이어 벽 너머는 전파하지 않음. 1홉 처리로 연쇄 폭증 방지 |
| 오프필드 | 모든 멤버의 부착·실드 타이머는 진행. 새 피격은 필드 캐릭터만. 기존 감전은 퇴장한 시전자와 독립적으로 진행 |
| 시간이 흐르는 기준 | Unity scaled deltaTime. 일시정지하면 타이머도 정지 |
| 표시 | 03번 고정 원소 팔레트, 임시 모델 색상, HUD 및 반응 로그 |

미정 수치와 소비·전파·실드 기본 정책은 관련 코드에도 주석으로 남겼습니다. 체력·사망·적 AI·고유 무기·원소 스킬/폭발 및 에너지 시스템은 추가하지 않았습니다. 누적 피해와 실드 흡수는 M1 반응을 관찰하기 위한 상태입니다. 탐사 기능, 지역 콘텐츠와 VFX 폴리싱도 이번 변경에 포함하지 않습니다.

## 자동 검증

Unity Editor의 **Window > General > Test Runner**에서 EditMode와 PlayMode를 실행하거나, Unity를 이 프로젝트에서 닫은 뒤 PowerShell로 실행합니다.

```powershell
Set-Location -LiteralPath 'D:\Project\ORBIS'
.\Tools\Test-M1.ps1 -UnityPath 'C:\Program Files\Unity\Hub\Editor\6000.6.0f1\Editor\Unity.exe'
```

이 스크립트는 M1 씬을 검증하고 **M0와 M1 전체 테스트**를 실행합니다. 결과는 `TestResults/M1-EditMode.xml`, `M1-PlayMode.xml` 및 각각의 로그입니다. `-Headless`를 추가하면 그래픽 장치 없이 실행하며 스크린샷은 생략합니다. 그래픽 테스트에서는 HUD를 제외한 실제 렌더를 `TestResults/M1_Prototype.png`로 저장합니다. TestResults와 Unity 캐시는 Git에서 제외됩니다.

2026-09-10 설치된 Unity 6000.6.0f1에서 최종 검증했습니다.

- Setup and Validate 성공: 두 씬의 스크립트 참조, 파티 조합, URP/Cinemachine/Input System 확인.
- **EditMode 62/62 통과**: M0 24개 + M1 원소 테스트 38개.
- **PlayMode 15/15 통과**: M0 7개 + M1 실제 씬·입력 통합 테스트 8개.
- M1 씬 렌더 PNG를 확인했습니다. 화 캐릭터 색상, 타깃 3개, 임시 검, 테스트 공간이 정상 표시됩니다.

검증은 동일 파일을 복제한 작업용 Unity 프로젝트에서 실행했으며, 최종 소스와 테스트 결과를 대상 저장소에 반영하고 파일 해시를 비교합니다. 독립 실행 파일 빌드는 이번 검증에 포함하지 않았습니다.
