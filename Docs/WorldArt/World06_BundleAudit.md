# World Step 6 — 실제 Packed 번들 감사

측정 입력: 기준 `buildlayout_2026.09.11.18.59.48.json` → 현재 `buildlayout_2026.09.11.19.25.36.json`. Unity 6000.6.0f1, 실제 파일 크기와 Addressables BuildLayout을 읽어 비교했다. 이 감사에서는 Unity 실행이나 Assets 변경을 하지 않았다.

| 압축 번들 | 기준 bytes (MiB) | 현재 bytes (MiB) |
|---|---:|---:|
| 아그니아 | 16,371,299 (15.613) | 5,166,748 (4.927) |
| 텔루나 | 16,025,186 (15.283) | 4,418,990 (4.214) |
| 자피르 | 17,912,136 (17.082) | 5,501,585 (5.247) |
| 그라니테 | 14,893,773 (14.204) | 4,196,408 (4.002) |
| 볼트하임 | 17,227,225 (16.429) | 6,226,658 (5.938) |
| 공유 환경 번들 | 0 | 12,462,217 (11.885) |
| 합계 | 82,429,619 (78.611) | 37,972,606 (36.213) |

실제 환경＋공유 번들 합계는 **44,457,013 bytes (42.398MiB, 53.93%) 감소**했다. 현재 빌드에는 기준 빌드에 없던 공동 PVS가 추가되어 있으므로, 이 값은 그 비용을 포함한 순변화다. M4 5번들의 이름·크기는 그대로이며, 전체 13개 현재 번들 파일이 존재하고 보고서 크기와 일치했다.

중복 asset은 **73 → 8개**다. 중복 객체의 추가 직렬화 데이터 합계는 **121,837,036 → 95,280 bytes** (116.193 → 0.091MiB, 99.92% 감소)다. 계산은 동일 GUID·객체 ID의 각 복사본 SerializedSize＋StreamedSize를 합한 뒤 가장 큰 단일 복사본 크기를 뺐다. 압축 파일 크기·RAM·VRAM과 다른 지표다.

공유 그룹에는 기존 데이터 **64개**가 등록됐고, 환경 5번들이 모두 동일 공유 번들에 의존한다. 등록 보고서의 기존 주소 보존·원본 바이트 보존 검사는 모두 통과했다. Native PVS는 공유 번들에 주소 1개로 기록되고 5개 환경 씬이 참조한다. 소스 베이크 감사는 10,583,248 bytes payload, 6씬, 1,554 Renderer 바인딩을 확인했다. 단, BuildLayout은 PVS를 `AssetType=0`, 크기 0으로 기록하므로 여기서 런타임 로드 크기나 실제 카메라 컬링 성공을 주장하지 않는다.

남은 8개 중복은 기존 UnifiedToon 셰이더, Resources 아래 Kenney 재질 5개, Kenney sign/obelisk 모델이다. 이들은 이번 World 데이터 공유 allowlist 밖에 있어 기존 주소·출처 구조를 유지했다. 전체 항목별 바이트는 같은 폴더의 `World06_BundleAudit.json`에 기록했다.

코어의 직접 참조와 Resources 때문에 플레이어 내장 데이터에 별도 사본이 생기는 문제는 Addressables 레이아웃만으로 전부 계산할 수 없다. 따라서 코어 충돌 메시·PVS 내장 사본이 제거됐다고 해석하지 않는다. 공유 번들은 의존 환경이 하나라도 로드된 동안 유지된다.

이 감사는 FPS·GPU/CPU 시간·VRAM 개선을 측정하지 않았다. 오클루전 대상은 고정 건축물과 큰 불투명 바위이며, 나무나 수동 인스턴싱 잔디가 PVS로 제거된다는 주장도 하지 않는다. 실제 플레이어에서 별도 검증해야 한다.
