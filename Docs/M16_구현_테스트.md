# M1.6 주인공 선택 · 원소 자유 전환 구현과 테스트

07번 기획서의 스텔라/폴라리스 선택을 기존 월드 진입 경로에 연결합니다. 두 주인공은 06번의 가챠 로스터 18명과 별개인 스토리 전용 캐릭터입니다. 이번 단계는 선택·저장·고정 파티 슬롯·원소 전환·공통 스킬을 구현하며 새 모델, 텍스처, 성별별 애니메이션이나 코스모 동행은 추가하지 않습니다. 두 선택지의 월드 외형과 기본 동작은 동일한 회색박스입니다.

## 시작 씬과 메뉴

- 선택 씬: `Assets/Orbis/M16/Scenes/M16_CharacterSelection.unity`
- 설정 메뉴: `Orbis > M1.6 > Setup and Validate`
- 씬 열기: `Orbis > M1.6 > Open Character Selection`
- 배치 실행 메서드: `Orbis.M16.Editor.ExplorerProjectSetup.SetupAndValidate`

설정 명령은 선택 씬을 첫 번째 활성 Build Settings 씬으로 등록하고 다른 씬과 활성 여부는 보존합니다. 선택을 확정하고 시작 버튼을 누르면 새 게임 씬 `Assets/Orbis/Game/Scenes/Orbis_OpenWorld.unity`에 진입합니다. 게임 씬이 아직 설치되지 않은 이전 구성에서는 M4 런처를 사용합니다. M0~M4와 M1.5의 개별 검증 씬은 유지합니다.

## 선택 흐름 확인

1. 설정 메뉴를 실행한 뒤 선택 씬을 열고 Play합니다. 새 저장 또는 이전 버전 저장은 미선택 상태입니다. 화면을 열고 기다려도 자동으로 주인공이 선택되거나 월드가 열리지 않아야 합니다.
2. `스텔라 / 여성형` 또는 `폴라리스 / 남성형` 카드의 선택 버튼을 누릅니다. 이 단계는 화면의 임시 후보만 바꾸며 저장을 확정하지 않습니다. 확정 전에는 다른 카드를 누를 수 있습니다.
3. `스텔라로 선택 확정` 또는 `폴라리스로 선택 확정`을 누릅니다. 선택과 초기 원소를 저장하고 카드를 잠급니다. 초기 원소의 기본값은 화입니다. 선택을 확정한 직후에도 시작 버튼을 누르기 전까지 월드에 들어가지 않습니다.
4. `여정 시작 / 이어하기`를 누르면 편집 가능한 아그니아 게임 씬으로 들어갑니다. 1번 슬롯이 선택한 주인공이며, 파티에서 주인공을 제거하거나 다른 주인공으로 바꾸지 않습니다.
5. Play를 종료하고 선택 씬을 다시 실행합니다. 저장한 이름과 이어하기 버튼이 나타나고 재선택은 비활성화되어야 합니다. 저장은 유지한 채 화면만 다시 열어도 자동 월드 진입은 일어나지 않습니다.

반대 성별의 최초 선택이나 미선택 거부를 반복 확인할 때에는 자동 테스트의 임시 프로필을 사용합니다. 이미 선택한 사용자의 기존 저장을 초기화하는 버튼은 만들지 않았습니다.

## 월드 조작과 확인

| 입력 | 동작 |
| --- | --- |
| 1 | 고정 1번 슬롯의 주인공으로 전환 |
| 2~4 | 기존 동료 슬롯 전환 |
| Tab | 화 → 수 → 풍 → 암 → 뢰 → 화 순서로 주인공 원소 전환 |
| G | 현재 주인공 원소의 공통 스킬 |
| 왼쪽 클릭 | 여정의 검 기본 공격. 물리 판정 |
| Q | 기존 궁극기 표현 경로 |

주인공을 활성화하고 Tab으로 다섯 원소를 순환시킵니다. 이름과 고정 슬롯은 유지되고 원소 표시가 바뀌어야 합니다. 원소 선택은 저장되어 다음 실행에서도 유지됩니다. 원소 전환에 모집 소유권이나 재화는 요구하지 않습니다. Tab/G는 Game 뷰의 게임 입력이 활성화된 동안만 작동하며, 궁극기·피격·사망 상태에서는 원소 변경이 잠시 제한됩니다.

G 스킬은 주인공이 지상에서 대기·이동 중일 때 사용할 수 있습니다. 시전 중 이동·점프·일반공격은 제한됩니다. 입력 해제나 공중·등반·수영 진입도 진행 중인 시전을 취소하지만 남은 재사용 시간은 유지합니다. 시전 중 2~4번 동료로 전환하면 진행 중인 시전은 취소되며, 다시 돌아와도 공통 재사용 시간은 초기화되지 않아야 합니다. 원소 변경이나 지역 이동으로도 재사용 시간이 초기화되지 않습니다. 시전 중 원소를 바꾸면 진행 중인 스킬은 시전 시작 시 원소로 처리하고 바뀐 원소는 다음 시전에 사용합니다. 다섯 원소 스킬은 같은 수치와 근접 동작의 기본값을 가지며 원소 부착과 기존 반응 체계로 연결됩니다.

이미 부착된 원소가 있는 표적에 다른 원소 스킬을 사용해 기존 증발·감전·과부하·확산·결정화 판정과 연결되는지 확인합니다. 기본 공격 자체는 선택 원소를 부착하지 않는 물리 공격입니다. 새 원소별 전용 애니메이션이나 VFX는 추가하지 않습니다.

## 데이터와 미정 기본값

`Assets/Orbis/M16/Resources/M16/Catalog.asset`에 다음 9개 ScriptableObject의 연결을 모았습니다.

| 데이터 | 위치 / 내용 |
| --- | --- |
| ExplorerDefinition 2개 | `Explorers/stella.asset`, `Explorers/polaris.asset`: 안정 ID, 이름, 선택 enum, 공유 무기 참조 |
| WayfarerWeaponDefinition 1개 | `WayfarersBlade.asset`: 여정의 검 / Wayfarer's Blade / Longsword |
| ExplorerSkillDefinition 5개 | `Skills/Fire.asset`, `Water.asset`, `Wind.asset`, `Rock.asset`, `Lightning.asset` |
| ExplorerCatalog 1개 | `Catalog.asset`: 두 주인공, 다섯 스킬, 공통 쿨다운과 초기 원소 |

두 ExplorerDefinition은 같은 무기 SO를 참조합니다. 캐릭터의 선택 ID는 `stella`, `polaris`, 무기는 `wayfarers_blade`, 스킬은 `explorer.fire/water/wind/rock/lightning`입니다. 가챠의 CharacterDefinition 18개나 보유 목록에 이 주인공들을 넣지 않습니다.

| 미정 수치 | 기본값 |
| --- | ---: |
| 공용 장검 기본 공격력 | 10 |
| 공통 스킬 피해 | 25 |
| 스킬 Range | 2.5m |
| 스킬 Radius | 0.85m |
| 시전 시간 | 0.5초 |
| 타격 시점 | 시전 후 0.25초 |
| 원소 부착 시간 | 4초 |
| 다섯 원소 공유 재사용 시간 | 2초 |
| 최초 선택 원소 | 화 |
| 피격 상태 지속 | 0.25초 |

모든 미정 수치는 소스 주석과 SO 기본값으로 명시했습니다. 설정 명령을 다시 실행해도 기존 SO GUID와 공격력·스킬 수치·공유 재사용 시간·초기 원소 편집값을 보존합니다. 데이터 ID와 공용 참조는 기준 구성을 다시 연결합니다. 기본 5개 스킬의 수치는 모두 같으며, 별도 연출·별도 동작 로직은 없습니다.

`Validate()`는 누락 참조, 두 선택지/다섯 원소의 중복, 잘못된 원소, 공유 무기 불일치, NaN/Infinity, 음수 쿨다운, 잘못된 사거리·지속시간·타격 시점을 거부합니다. `Catalog.Get(Unselected)`와 `Skill(None)`도 거부하여 미선택 데이터를 주인공 정의로 사용할 수 없게 합니다.

## 저장과 진입 API

선택 정보는 기존 `Application.persistentDataPath/Orbis/m4-progress.json`의 저장 버전 3에 `explorer.choice`와 `explorer.element`로 저장합니다. 버전 1/2를 읽을 때 기존 재화, 모집 소유권과 천장, 위임 및 보스 기록을 보존하며 주인공만 미선택/None으로 이전합니다. 신규 선택이나 원소 변경도 기존 원자적 저장 경로를 사용하며 실패한 저장은 진행 상태를 변경하지 않습니다.

선택 화면의 `Choice`는 `ExplorerJourney.Profile.GetExplorerSnapshot().choice`를 읽고 `Candidate`는 UI의 임시 후보입니다. `Select(ExplorerChoice)`와 `BeginJourney()`는 각각 `ExplorerJourney.Select`와 `ExplorerJourney.BeginJourney`를 호출합니다. `Awake`에서는 데이터·저장값 읽기와 UI용 카메라 생성만 하며 주인공 선택, 파티 생성, 월드 로드는 수행하지 않습니다.

원소 변경과 주인공 선택은 가챠 소유권과 별개입니다. 스킬 쿨다운은 플레이 중의 게임 시계로 공유하며 원소/파티 전환으로 초기화하지 않습니다. 재실행에 보존되는 데이터는 선택과 원소이고, 남은 쿨다운을 세이브 파일에 추가하지 않습니다. 이어하기는 저장된 주인공·원소로 아그니아 시작점에 진입하며, 마지막 지역·위치·활성 동료는 재실행 시 복원하지 않습니다. 플레이 중 지역 이동은 동료 ID를 우선 복원하지만 목적지 파티에 그 동료가 없으면 주인공이 활성화됩니다.

## 자동 검증

자동 테스트는 GUID로 구분한 임시 저장 경로를 사용하고, 월드 통합 테스트는 `M4Session`에 임시 프로필을 주입합니다. 사용자 실제 저장은 건드리지 않습니다. v1/v2 저장 이전, 최초 선택과 재선택 거부, 다섯 원소 저장, 저장 실패 롤백, 잘못된 저장 보호, 고정 슬롯, 물리 공격과 원소 부착, 시전 스냅샷·쿨다운, 주인공 선택 화면·월드 이동을 점검했습니다.

Unity 6000.6.0f1에서 설정/컴파일 검증과 전체 테스트 **338개**가 통과했습니다. EditMode **288/288**, PlayMode **50/50**, 실패·건너뜀 0개입니다. 결과는 `TestResults/M16-setup.log`, `TestResults/M16-EditMode.xml`, `TestResults/M16-EditMode.log`, `TestResults/M16-PlayMode.xml`, `TestResults/M16-PlayMode.log`에 있습니다.

재실행은 Unity Test Runner의 EditMode/PlayMode 각각 `Run All`을 사용합니다. 배치 실행은 프로젝트 경로와 결과 경로를 지정합니다.

```powershell
& 'C:\Program Files\Unity\Hub\Editor\6000.6.0f1\Editor\Unity.exe' -batchmode -projectPath 'D:\Project\ORBIS' -runTests -testPlatform EditMode -testResults 'D:\Project\ORBIS\TestResults\M16-EditMode.xml' -logFile 'D:\Project\ORBIS\TestResults\M16-EditMode.log'
& 'C:\Program Files\Unity\Hub\Editor\6000.6.0f1\Editor\Unity.exe' -batchmode -projectPath 'D:\Project\ORBIS' -runTests -testPlatform PlayMode -testResults 'D:\Project\ORBIS\TestResults\M16-PlayMode.xml' -logFile 'D:\Project\ORBIS\TestResults\M16-PlayMode.log'
```

일반 게임 흐름은 기존 PlayerMotor/Animator를 재사용합니다. Idle/Move/Attack은 기존 이동·콤보가 구동하고, Skill/Burst/Hurt/Dead는 같은 모터의 행동 잠금 상태로 연결했습니다. G는 기존 Attack1 클립, Burst/Hurt/Dead의 캐릭터 자세는 기존 Idle 클립을 재사용하며 Q의 카메라·Timeline은 기존 M3 경로입니다. 새로운 전용 애니메이션은 포함하지 않습니다. HP 회복·사망 후 구조 처리도 기존 월드 규칙을 따릅니다.
