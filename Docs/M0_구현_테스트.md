# M0 구현 및 테스트

## 기준과 범위

- 기준 문서: `기획서/01~05`, 특히 `05_기술스택_로드맵.md`의 M0.
- 캐릭터 1인: 01의 장검 사용자 이그니스 컨셉. 외부 모델 없이 직접 구성한 Unity 기본 도형과 자체 작성 애니메이션을 사용합니다.
- 3인칭 CharacterController 이동, 걷기/달리기/점프, Cinemachine 추적·회전·장애물 회피, 지상 3단 콤보, Animator와 커스텀 콤보 FSM.
- 표적은 기본공격의 적중을 확인하는 피격 카운터입니다.
- M1~M4 기능인 파티, 원소 부착/반응, 탐사 확장, 스킬/궁극기, VFX/히트스톱/화면 흔들림, 콘텐츠 확장은 포함하지 않았습니다.
- 02의 스태미나는 이번에 지정된 M0 기능 목록에 포함되지 않아 달리기 지속 시간을 제한하지 않습니다.
- 사용자 확정 조작 정책: 공격 중 이동·점프 제한, 각 타 시작 시 입력 방향으로 회전, 지상 기본공격 3단.

## 기술 스택

| 항목 | 고정 버전 |
|---|---|
| Unity Editor | 6000.6.0f1 (Unity 6) |
| URP | 17.6.0 |
| Cinemachine | 6.6.0 |
| Input System | 1.20.0 |
| Unity Test Framework | 1.8.0 |

설치된 Unity 6 Editor와 함께 제공되는 URP/Cinemachine 버전에 맞췄습니다. 패키지 버전은 `Packages/manifest.json`과 Unity가 생성한 `packages-lock.json`에 기록됩니다. Active Input Handling은 Input System Package로 설정했습니다.

공식 참고: [Unity 6 Cinemachine](https://docs.unity3d.com/6000.0/Documentation/Manual/com.unity.cinemachine.html), [Input System](https://docs.unity3d.com/Packages/com.unity.inputsystem@1.20/manual/index.html). 구현 API는 실제 설치된 패키지 소스와 컴파일로 확인합니다.

## 씬과 에셋

실행 씬: `Assets/Orbis/M0/Scenes/M0_Prototype.unity`.

씬의 `M0SceneBootstrap`이 Play 진입 시 플레이어, 아레나, 조명, 카메라, 표적을 구성합니다. Inspector의 실행 중 수치 변경은 Play 종료 시 초기화됩니다. 지속적으로 기본값을 조정하려면 해당 스크립트의 주석 달린 필드 초기값을 수정합니다.

URP 설정, 머티리얼, 7개 애니메이션 클립과 Animator Controller는 프로젝트 에셋으로 포함됩니다. Editor의 `M0ProjectSetup`은 누락된 에셋만 생성합니다. 기존 클립과 머티리얼 수정값은 덮어쓰지 않습니다. 복구 및 검증 메뉴는 **Orbis > M0 > Setup and Validate**입니다.

- `Main Camera`: URP Camera + CinemachineBrain.
- `Camera Rig`: 캐릭터 회전과 독립된 추적 피벗.
- `M0 Cinemachine Third Person Camera`: CinemachineCamera + CinemachineThirdPersonFollow.
- `Player/Visual`: Animator, Torso/Head와 팔·다리 피벗, 장검.
- Animator 상태: Idle, Walk, Run, Jump, Attack1, Attack2, Attack3.
- 물리 레이어: World 8, TrainingTarget 9, Player 10.
- 공격 시간은 `ComboSequence`가 소유하고 `BasicAttackCombo`가 같은 진행률로 공격 포즈와 피격 판정을 구동합니다.
- 공격마다 표적 중복 피격을 막고, World 콜라이더 뒤의 표적은 피격시키지 않습니다.

초반 클릭은 저장하지 않으며 현재 타 후반에 **다음 한 타**만 예약합니다. 3타 중 입력은 다음 콤보로 자동 이월하지 않습니다. 버튼을 누르고 있는 것만으로 연속 공격하지 않습니다. 점프 버퍼·코요테 타임은 추가하지 않았고 공중 재점프·공중 공격을 허용하지 않습니다.

## 수동 테스트

1. **기본 씬:** Unity Hub에서 저장소를 열고 임포트 완료 후 `M0_Prototype.unity`를 열어 Play. 캐릭터, 격자 바닥, 주황색 표적과 디버그 패널이 보여야 합니다.
2. **이동:** WASD로 걷고 Shift로 달립니다. Shift를 놓으면 바로 걷기로 복귀합니다. 대각선이 직선보다 빨라지지 않아야 합니다.
3. **시점:** 마우스로 시점을 90°/180° 돌린 뒤 W를 누릅니다. 화면 앞 방향으로 이동해야 하며 상하각이 제한돼야 합니다.
4. **점프:** Space로 점프하고 공중에서 다시 눌러봅니다. 한 번만 뛰고 착지 후 다시 점프할 수 있어야 합니다.
5. **지형:** 오른쪽 낮은 계단과 0.9m 플랫폼, 왼쪽 경사로를 이동합니다. 뒤쪽 벽을 향해 달려도 통과하지 않아야 합니다. 오른쪽 낮은 천장 아래에서 점프하면 머리 충돌 후 내려와야 합니다.
6. **카메라 충돌:** 시작점 뒤쪽 벽(z=-6) 가까이 이동합니다. 카메라가 벽 앞쪽으로 당겨지고 벗어나면 원래 거리로 돌아와야 합니다.
7. **단타:** 표적을 바라보고 왼쪽 클릭 한 번. Attack1 후 Ready로 돌아오며 한 타에 표적 피격 횟수는 최대 1만 증가합니다.
8. **콤보:** 1타 후반, 2타 후반에 각각 클릭. Attack1→Attack2→Attack3 이후 Ready로 복귀합니다. 입력 예약 여부와 피격 횟수를 HUD로 확인합니다.
9. **끊기·연타:** 클릭을 중단하면 현재 타만 마치고 종료합니다. 다음 클릭은 Attack1입니다. 빠르게 연타하거나 버튼을 오래 눌러도 타수가 한 번에 건너뛰거나 무한 공격하지 않아야 합니다.
10. **공격 중 입력:** 공격 중 WASD와 Space를 누릅니다. 이동·점프는 막히며 현재 타 도중에는 몸 방향이 고정됩니다. 예약된 다음 타 시작에서만 현재 이동 입력 방향을 바라봅니다.
11. **복귀:** 공격 종료 시 이동 입력을 계속 누르고 있으면 즉시 이동과 Walk/Run 애니메이션으로 복귀해야 합니다.
12. **포커스:** Esc/Alt-Tab 후 이동·공격이 멈춰야 합니다. 돌아와 Game 뷰를 클릭하면 조작이 재개되며 재획득 클릭 자체는 공격하지 않아야 합니다.
13. **초기화:** R로 시작 위치와 표적 피격 횟수를 초기화합니다.

## 자동 테스트

Unity 메뉴 **Window > General > Test Runner**에서:

- **EditMode > Run All**: 콤보 시간/버퍼/리셋/긴 프레임과 실제 물리 중복 피격·벽 차단 검증.
- **PlayMode > Run All**: 가상 Input System 장치를 통한 실제 이동·점프·카메라·공격·커서 흐름 검증. 인터랙티브 실행 시 Game 뷰에 포커스를 둡니다.

PowerShell에서 설치된 Editor 경로를 지정하여 실행할 수도 있습니다.

```powershell
./Tools/Test-M0.ps1 -UnityPath 'C:\Program Files\Unity\Hub\Editor\6000.6.0f1\Editor\Unity.exe'
```

테스트 결과 XML 및 로그는 `TestResults/`에 생성되며 Git에서 제외됩니다. 그래픽을 지원하는 PlayMode 실행은 초기 씬 PNG도 이 폴더에 저장합니다.

Unity 없는 환경의 순수 콤보 검증용 C# 소스는 `Tools/Tests/ComboSequenceHarness.cs`입니다. 이 검증은 Unity 컴파일·물리·렌더 테스트를 대체하지 않습니다.

## 이번 실행의 검증 결과

2026-09-10, 설치된 Unity 6000.6.0f1에서 수행했습니다.

- 프로젝트 컴파일 및 `M0ProjectSetup.SetupAndValidate`: 통과.
- Unity EditMode: **24개 통과, 실패 0개**. 실제 씬 참조, Animator 클립 길이, 콤보 FSM, 물리 피격, 애니메이션 시간 복원을 포함합니다.
- Unity PlayMode: **7개 통과, 실패 0개**. 실제 Input System 이벤트로 이동·점프·공격·카메라·벽·천장·입력 재획득을 검증했습니다.
- 순수 C# 콤보 하네스: **31개 검증 통과**.
- 배치 테스트에 한해 Editor 입력 전달 설정을 저장/변경/복구합니다. 일반 실행의 Game 뷰 포커스·커서 정책은 그대로 유지합니다.
- URP 카메라 렌더 PNG를 직접 확인해 캐릭터·표적·지형의 배치와 재질 색상을 점검했습니다. 캡처는 셰이더 동기 준비 후 수행하며 IMGUI 디버그 패널은 카메라 PNG에 포함되지 않습니다.
- Windows 실행 파일 빌드는 수행하지 않았습니다. 검증 대상은 Unity Editor의 프로토타입 씬입니다.
