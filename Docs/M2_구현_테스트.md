# M2 구현 및 테스트

## 실행

1. Unity Hub에서 `D:\Project\ORBIS` 프로젝트를 연다. 지정 에디터는 `ProjectSettings/ProjectVersion.txt`의 **Unity 6000.6.0f1**이다.
2. 패키지 임포트와 컴파일이 끝나면 **Orbis > M2 > Setup and Validate**를 실행한다. M0/M1의 URP·Animator 리소스를 재사용하며, 누락된 M2 머티리얼만 생성한다.
3. **Orbis > M2 > Open Exploration Prototype**으로 `Assets/Orbis/M2/Scenes/M2_ExplorationPrototype.unity`를 연다. 메뉴는 Unity의 저장 확인을 거쳐 해당 씬 하나만 연다. 저장 확인에서 취소하면 씬 전환도 취소한다.
4. Play를 누르고 Game 뷰를 클릭한다. 좌측 HUD에서 이동 모드, 공용 스태미나, 퍼즐·도전 진행과 보상을 확인한다. 작은 Game 뷰에서는 Esc로 커서를 해제한 뒤 HUD를 스크롤할 수 있다.

씬의 지형과 플레이어는 Play 시작 시 만들어진다. 편집 모드의 Hierarchy에 부트스트랩 하나만 있는 것은 정상이다.

## 구현 범위

60 × 55m 크기의 그레이박스 지역 하나에 다음을 배치했다.

- 기존 M0의 걷기·달리기·점프·3단 공격과 Cinemachine 카메라, M1의 4인 전환·원소 반응.
- 8m 절벽의 등반, 고지대에서의 활공, 깊이 3m인 물속 이동과 완만한 해안으로 걸어 나오기.
- 파티가 함께 사용하는 스태미나, 소진에 따른 행동 종료, 낙하 피해와 수영 소진 시 구조.
- Fire로 석상 I → II → III을 점화하는 필드 퍼즐 하나와 상자 보상.
- 제한 시간 내 표적 세 개에 각각 증발을 일으키는 도전방 하나와 완료 보상.

캐릭터는 M0의 공유 아바타를 사용한다. 등반·활공·수영은 기존 공중 포즈를 임시로 재사용한다. 활공 중에는 판과 지지대로 만든 단순 글라이더가 표시된다. 원소와 퍼즐 진행은 색상·HUD·로그로 표현한다. 고유 무기·스킬, 적 전투 AI, 추가 지역, VFX 폴리싱은 포함하지 않는다. 보상은 플레이 세션의 강화 재료 카운터이며 일반 인벤토리나 저장 파일 시스템이 아니다.

## 조작

| 입력 | 동작 |
|---|---|
| WASD | 카메라 기준 지상 이동·활공 방향·수평 수영 |
| Shift | 달리기 |
| Space | 지상 점프; 공중에서 누르면 활공 전개/해제; 물속에서 누르고 있으면 상승 |
| E | 가까운 등반 가능 벽 잡기/놓기 |
| 등반 중 W/S, A/D | 위/아래, 좌/우 이동 |
| 물속 Left Ctrl | 하강 |
| 1 / 2 / 3 / 4 | Ignis(Fire) / Maris(Water) / Sparkle(Lightning) / Aura(Wind) 전환 |
| 마우스 / 왼쪽 클릭 | 카메라 회전 / 기본공격 |
| F | 2.5m 안의 필드 상자 수령, 도전 시작·재시도·완료 보상 수령 |
| Esc | 커서 해제; Game 뷰를 클릭하면 다시 조작 |
| R | 스폰 복귀, 이동·스태미나·원소 상태·미수령 콘텐츠 진행 초기화 |

M1 검증 키 F6~F9는 이 씬에서 동작하지 않는다. 파티 전환 중에도 플레이어 위치·카메라·이동 모드와 공용 스태미나를 이어서 사용한다.

### 테스트 위치 이동

아래 키는 테스트용 위치 이동이다. 공격과 속도를 정리하고 몸과 카메라를 +Z 방향으로 맞춘다. **스태미나는 채우지 않는다.** 완전히 초기화하려면 R을 먼저 누른다.

| 키 | 위치 | 좌표와 용도 |
|---|---|---|
| F1 | 지상 스폰 | `(0, 0.1, 0)` |
| F2 | 절벽 앞 | `(0, 0.1, 11.4)`; 앞쪽 +Z의 벽을 E로 잡기 |
| F3 | 절벽 정상 | `(0, 8.1, 16)`; 북쪽 끝으로 이동해 활공 |
| F4 | 깊은 물 | `(-18, -0.5, 16)`; 잠수·부상·구조 확인 |
| F5 | 필드 퍼즐 앞 | `(14, 0.1, 5.5)`; 석상까지 직접 접근해서 공격 |
| F10 | 도전방 입구 표식 | `(14, 0.1, 21.5)`; F로 시작·재시도·보상 수령 |

위치 이동 직후에는 벽 재잡기 방지 시간이 잠시 적용된다. F2를 누르고 약 0.2초 뒤 E를 누르면 된다.

## 수치와 소진 규칙

기획서 02의 소모량은 그대로 적용했다. 그 밖의 수치는 **미정 기본값**이다.

| 항목 | 값 |
|---|---|
| 공용 최대 스태미나 | 100 — 미정 기본값 |
| 달리기 | 연속 3초까지 무료, 이후 초당 2 |
| 등반 | 초당 8; 벽에 가만히 매달려 있어도 소모 |
| 활공 | 초당 5 |
| 수영 | 초당 6; 물에 떠서 가만히 있어도 소모 |
| 회복 | 마지막 소모로부터 1초 뒤 초당 15 — 미정 기본값 |
| 회복 가능한 행동 | 지상 대기·걷기만. 지상 공격·공중·수영·등반·활공·달리기에는 회복하지 않음 |
| 등반/활공/수영 속도 | 각각 2 / 5 / 3m/s — 미정 기본값 |
| 활공 하강 / 수중 수직 이동 | 각각 2.2 / 2m/s — 미정 기본값 |

- 달리기 소진 시 걷기로 내려간다. 달리기를 계속 누른 경우에는 15 이상으로 회복해야 다시 달릴 수 있다.
- 등반 소진 시 벽에서 떨어진다. 이때 착지 피해는 최소 5다. 잔량 10 미만에서는 새로 벽을 잡을 수 없다.
- 활공 소진 시 일반 낙하로 전환된다. 잔량 5 미만에서는 활공을 새로 펼칠 수 없다. 지면 바로 위에서는 펼칠 수 없다.
- 일반 낙하가 **3m를 초과**하면 `5 + (3m 초과 거리 × 0.5)` 피해를 적용하며 최대 20이다. 활공 중 천천히 내려온 구간은 일반 낙하 거리로 누적하지 않는다.
- 수영 소진 시 마지막 안전한 육지 위치로 즉시 복귀하고 환경 피해 5를 받으며 스태미나를 25로 설정한다. 이후 지상 회복 조건에 따라 다시 회복한다.
- 낙하·구조 피해는 당시 활성 파티원의 원소 액터에도 연결되며 HUD의 활성 파티원 Damage에서 확인할 수 있다. 전환한다고 공용 스태미나가 새로 채워지지 않는다.

## 수동 검증 순서

### 지상 이동과 공용 스태미나

1. R로 초기화한다. 걷기·달리기·점프·공격·1~4 전환을 확인한다.
2. Shift+W로 3초 이상 연속 달린다. 첫 3초 뒤부터 스태미나가 초당 2씩 줄어드는지 확인한다.
3. 1~4로 바꾸어도 잔량이 유지되는지 확인한다.
4. 달리기를 멈추고 지상에서 대기하거나 걷는다. 마지막 소모 1초 후부터 회복되는지 확인한다. 공격을 계속하는 동안은 회복하지 않아야 한다.

### 절벽과 활공

1. R → F2를 누른다. 절벽 전면은 `z=12`, 높이는 8m이며 앞을 보는 상태에서 E로 잡을 수 있다.
2. E로 잡은 뒤 W를 누른다. HUD가 `Climbing`이고 스태미나가 초당 8씩 줄어드는지 확인한다. A/D와 S도 확인한다.
3. 계속 올라가면 정상으로 올라선다. 도중에 E를 다시 누르면 떨어진다. 벽에 매달린 채 잔량을 소진했을 때도 떨어지고 착지 시 피해가 기록되는지 확인한다.
4. R → F3를 누른다. 정상에서 +Z 방향으로 이동하면 `z=20`에 끝이 있다. 끝에서 점프하거나 걸어 나간 뒤 공중에서 Space를 눌러 활공한다.
5. HUD의 `Gliding`, 초당 5 소모, 완만한 하강과 방향 이동을 확인한다. 공중에서 Space를 다시 누르면 활공이 해제된다. 착지하면 지상 이동으로 돌아와야 한다.
6. 스태미나가 적은 상태에서 F3로 이동하면 활공 소진을 빠르게 확인할 수 있다. 테스트 위치 이동은 잔량을 유지한다.

### 물속 이동과 해안

1. R → F4를 누른다. 수면은 `y=0`, 바닥은 `y=-3`이다. 잠시 가라앉으면 `Swimming`으로 바뀐다.
2. Left Ctrl을 눌러 잠수한다. 머리까지 수면 아래로 내려가면 HUD에 `UNDERWATER`가 표시된다. 바닥을 뚫고 내려가지 않아야 한다.
3. Space를 누르고 있으면 수면까지 올라간다. 수면에서는 머리를 물 위로 내놓고 떠 있어야 한다.
4. 카메라가 초기 방향인 상태에서 D를 눌러 동쪽으로 이동한다. `x=-15`에서 시작하는 해안이 `x=-7, y=0`까지 약 20.6도로 올라간다. 이 경사를 따라 물 밖으로 나오면 지상 이동으로 복귀한다.
5. 다시 R → F4 후 떠서 기다린다. 물에 가만히 있어도 소모된다. 0이 되면 마지막 안전 육지로 복귀하고 구조 횟수가 늘며 스태미나가 25가 되는지 확인한다. 육지에서 회복이 이어져 잔량은 곧 25보다 커질 수 있다.

### 필드 퍼즐과 상자

1. R → F5 → 1을 누른다. 전면 막대 수가 I, II, III인 석상이 왼쪽부터 놓여 있다.
2. 석상 발 위치는 `(11,0,8)`, `(14,0,8)`, `(17,0,8)`이다. F5 위치에서는 바로 닿지 않으므로 원하는 석상 앞으로 이동해, 대략 `z=6.4~6.8`에서 +Z를 바라보고 공격한다.
3. Ignis의 Fire 공격을 **왼쪽 I → 가운데 II → 오른쪽 III** 순서로 각각 맞힌다. 켜진 석상은 주황색이고 HUD의 Lit 수가 증가한다.
4. 이미 켜진 석상에 같은 Fire 콤보가 다시 맞는 것은 무시한다. 다음 순서를 틀리거나 다른 원소를 맞히면 미완료 진행이 초기화된다. 확산으로 전달된 원소는 직접 점화로 인정하지 않는다.
5. 세 석상이 켜지면 뒤편 `(14,0,10.5)`의 상자가 금색으로 변한다. 상자에서 2.5m 안으로 접근해 F를 누르면 뚜껑이 열리고 강화 재료 5개를 받는다.
6. F 반복, R 초기화, 같은 Play 세션의 씬 재로드로 같은 상자 보상을 다시 받을 수 없어야 한다.

### 도전방

1. F10을 누른 뒤 입구의 금색 바닥 표식에서 F를 누른다. 미정 기본값은 **60초 안에 표적 세 개에 각각 증발 1회**다.
2. 표적은 `(11,0,26)`, `(14,0,28)`, `(17,0,26)`에 있다. 표적 앞으로 이동하고 1번 Ignis로 Fire를 맞힌 뒤 2번 Maris로 바꾸어 Water를 맞힌다. Water → Fire의 반대 순서도 인정한다.
3. 각 표적에서 증발이 한 번 발생하면 완료 수가 늘고 녹색으로 바뀐다. 완료된 표적을 반복해서 맞혀 전체 목표 수를 채울 수 없다. 다른 반응은 목표로 인정하지 않는다.
4. 세 개를 끝내면 `Completed`가 된다. 보상은 자동 지급되지 않는다. 입구 표식으로 돌아와 2.5m 안에서 F를 눌러 강화 재료 3개를 받는다.
5. 시간을 넘기면 `Failed`가 된다. 입구에서 F로 재시작하면 시간·표적 상태·진행이 초기화된다. R도 미수령 도전 진행을 초기화한다.
6. 필드 상자와 도전 보상을 모두 받으면 합계는 8개다. 보상 수령 기록은 같은 Play 세션에서 R과 씬 재로드 후에도 유지된다. Play를 종료하고 다시 시작하면 새 세션으로 초기화된다.

## 자동 테스트

프로젝트를 같은 Unity Editor에서 열어 둔 상태라면 닫고, 프로젝트 루트의 PowerShell에서 실행한다.

```powershell
.\Tools\Test-M2.ps1 -UnityPath 'C:\Program Files\Unity\Hub\Editor\6000.6.0f1\Editor\Unity.exe'
```

스크립트는 M2 설정 검증 후 전체 EditMode·PlayMode 테스트를 실행한다. 기존 M0/M1 회귀 테스트도 포함한다. 그래픽 출력이 필요 없는 실행에는 `-Headless`를 추가할 수 있으며, 시각 확인은 일반 실행에서 수행한다.

결과 위치:

- `TestResults/M2-setup.log`
- `TestResults/M2-EditMode.xml`, `TestResults/M2-EditMode.log`
- `TestResults/M2-PlayMode.xml`, `TestResults/M2-PlayMode.log`

2026-09-10 설치된 Unity 6000.6.0f1에서 최종 검증했다.

- **Setup and Validate 성공**: M0/M1 리소스 재사용, M2 씬 참조와 8개 재질을 검증했다.
- **EditMode 97/97 통과**: 기존 M0/M1 62개 + M2 스태미나 20개·콘텐츠 15개.
- **PlayMode 24/24 통과**: 기존 M0/M1 15개 + 실제 M2 씬·입력 통합 검증 9개.
- `TestResults/M2_Prototype.png`로 실제 씬 렌더를 확인했다. HUD는 해당 캡처에 포함되지 않는다.

테스트는 대상 소스를 복제한 작업용 Unity 프로젝트에서 수행했다. 검증한 소스와 결과를 대상 저장소에 반영하고 해시로 동일성을 확인한다. 독립 실행 파일 빌드는 이번 검증에 포함하지 않았다.

전체 변경·생성 파일은 [M2_FILES.md](M2_FILES.md)에 정리했다.

## M0/M1 재사용 경계

- `Assets/Orbis/M0/Runtime/Presentation/M0SceneBootstrap.cs`의 `BuildEnvironment`는 기본값이 true다. M2에서는 false로 두어 M0의 지형·조명·더미 생성을 건너뛰고 플레이어와 카메라만 재사용한다.
- `Assets/Orbis/M1/Runtime/Presentation/M1SceneBootstrap.cs`의 `BuildEnvironment`, `ShowHud`, `EnableDebugKeys`도 기본값은 true다. M2는 세 값만 false로 설정하고 파티·원소 연결·공유 아바타를 재사용한다.
- `Assets/Orbis/M0/Runtime/Player/PlayerMotor.cs`에 연결된 `IPlayerTraversal`을 M2의 `ExplorationMotor`가 구현한다. 기존 이동·공격 코드가 M2 상태와 입력을 동시에 처리하지 않도록 이동 모드의 소유권을 나눈다.
