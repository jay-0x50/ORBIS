# STEP 3 콘텐츠 분산 배치

`WorldContentRedistribution.Apply(M4SceneBootstrap world)`는 현재 열려 있는 섬 씬의 기존 퍼즐 및 도전의 방 루트를 이동한다. 새 게임플레이 오브젝트를 생성하거나 M4 설정을 다시 구성하지 않는다. 씬 저장 및 반환된 `Vector4(x,y,z,radius)` 영역의 식생 정리는 호출하는 `WorldLandmarkBuilder`가 담당한다.

## 배치 기준

기획서에 없는 아래 값은 테스트용 기본값이다.

| 항목 | 기준 |
| --- | --- |
| 허브 중심 | 기존 M4IslandRegion.Center 유지 |
| 후보 반경 | 허브에서 90, 94, 102, 110, 118, 126m |
| 퍼즐 ↔ 도전의 방 | 중심 사이 60~180m; 두 feather 영역 사이 최소 16m 확보 |
| 퍼즐 지형 | 평탄 반경 12m, 바깥 feather 반경 20m |
| 도전의 방 지형 | 평탄 반경 14m, 바깥 feather 반경 24m |
| 기존 허브 보호 | 65m 원형 영역에 높이 변경 없음; feather 바깥까지 2m 추가 여유 |
| 접근길 | 중심 폭 4m, 흙 칠하기 바깥 폭 10m; 최대 종단 경사 rise/run 0.42 |
| 완충 지형 경사 | 최대 rise/run 0.50, 기존 높이 대비 변경 4.5m 이내 |

후보지의 높이는 저장된 TerrainData의 높이맵을 직접 보간한다. 월드 생성 공식의 높이를 다시 계산하지 않는다. 현재 지형에서 안전한 직선 접근로가 있는 가까운 후보를 고르며, 길을 위한 높이 계단이나 광역 지형 평탄화는 추가하지 않는다. 기존 보스 경기장에서는 접근길이 23m 이상 떨어진다. 바다 및 기존 담수 트리거 안의 잠긴 지점은 제외한다.

산악 지역에서 80~130m 간격으로 제한하면 경사 조건을 만족하는 후보끼리 조합할 수 없는 경우가 확인되어, 임시 간격 기준을 60~180m로 넓혔다. 경사·침수·허브 보호 조건은 그대로 유지한다. 실제 선택된 콘텐츠 사이 거리는 감사 JSON의 `contentSeparation`에 기록된다.

퍼즐 중심은 순서가 있는 세 석상의 평균 위치, 도전의 방 중심은 기존 세 표적의 평균 위치다. 지역별 실제 최종 좌표는 Unity 빌드 시 생성되는 `TestResults/WorldDev/World03_ContentLayout.json`에 기록된다. 실행 전에는 특정 후보가 채택됐다고 가정하지 않는다.

## 보존과 재실행

퍼즐/도전의 방 루트 전체를 평행 이동한다. 석상 및 표적의 배열 순서, SourceId, 상자 및 입구 참조는 그대로 유지된다. M4AuthoredRegion, 지역 중심, 보스, 스폰, NPC, 이동 포털, 조사 지점은 이동하지 않는다. `M4AuthoredRegion.CreateLayout()`은 이동한 기존 참조에서 새 위치를 읽는다. 기존 보상 키 `m4.<Id>.puzzle`, `m4.<Id>.challenge` 및 보스 원소·약점 정의는 바꾸지 않는다.

두 콘텐츠가 이미 보호 구역 밖에서 유효한 간격으로 배치돼 있으면 저장된 좌표를 그대로 재사용하고 지형 feather를 반복 적용하지 않는다. 흙길 칠하기도 최대 목표 가중치로 적용하며 원래 Trail 채널을 유지한다. 한쪽만 옮겨진 비정상 중간 상태는 임의로 덮어쓰지 않고 오류로 알려준다.

## 검증할 내용

- STEP 3 빌드가 다섯 지역에 총 10개 배치를 만들고 감사 JSON을 기록하는지 확인한다.
- 실제 게임에서 새 퍼즐/도전의 방까지 이동하여 석상 순서, 상자 보상, 도전 시작·완료가 유지되는지 확인한다.
- 새 표적 및 입구의 발밑에 Terrain이 있고, 경계의 급격한 단차와 식생 관통이 없는지 확인한다.
- 같은 빌드를 재실행했을 때 콘텐츠 위치와 지형 높이가 달라지지 않는지 확인한다.

이 문서는 구현 기준을 설명한다. 실행 성공 및 최종 좌표는 실제 Unity 빌드와 테스트 결과로 별도 확인해야 한다.
