# 통합 섬과 원화 기반 주인공 — 실행 안내

## 게임 실행

Unity 6에서 `Orbis > Game > Open Unified Island`를 실행한 뒤 Play를 누른다.
`Orbis > Game > Open Open World`도 새 섬이 있으면 같은 씬을 연다.
씬 파일: `Assets/Orbis/Game/Scenes/Orbis_Island.unity`.

저장된 주인공 선택이 없으면 스텔라 / 폴라리스 선택 화면이 섬 위에 나타난다. 선택하고 시작하면 같은 씬의 자피르 초원에서 출발한다. 이미 선택한 저장 파일은 해당 주인공으로 바로 시작한다. 종전 `Orbis_OpenWorld.unity`와 M0~M4 테스트 씬은 개별 회귀 테스트용으로 보존한다.

## 섬 구성

- 지형 범위: 2,000 × 2,000m. 1,000m Terrain 타일 4개가 한 씬에서 연결된다. 이 범위에는 바다와 해안이 포함된다.
- 저장된 높이장 실측 육지 면적은 약 2.329km²(전체 범위의 58.2%)이고, 최고 지면은 약 204m다. 상세 측정값은 `TestResults/Island-Map-Metrics.txt`에 있다.
- 기준은 몬드의 탐험 규모감이며, 몬드의 실측 크기나 동일 콘텐츠 밀도를 주장하지 않는다.
- 순환길 중심선 길이는 약 3.8km. 이동 속도와 스태미나는 기존 설정을 유지한다.
- 편집 모드 Hierarchy에 Terrain, 다섯 지역 콘텐츠, 마을·풍차·광산·첨탑, 수역, 식생과 조명이 저장되어 있다. 플레이 시작 시 지형을 새로 만드는 구조가 아니다.
- 다섯 구역이 플레이어·파티·카메라·원소 반응 매니저 하나를 공유한다. 걸어서 경계를 넘을 수 있고, 별도 지역 씬 로딩은 없다.

| 구역 | 원소 | 중심 좌표 X/Y/Z (m) | 환경 / 기존 콘텐츠 |
|---|---|---|---|
| 아그니아 고원 | 화 | -520 / 90 / 340 | 화산 고원·분화구, 화 석상, 증발 도전, 수 약점 보스 |
| 텔루나 군도 | 수 | 520 / 12 / -380 | 해안·작은 섬·야자수, 수 석상, 감전 도전, 뢰 약점 보스 |
| 자피르 초원 | 풍 | 0 / 25 / -180 | 초원·마을·풍차, 풍 석상, 확산 도전, 암 약점 보스 |
| 그라니테 산맥 | 암 | -450 / 115 / -450 | 산맥·광산, 암 석상, 결정화 도전, 화 약점 보스 |
| 볼트하임 | 뢰 | 450 / 90 / 430 | 고지대·첨탑, 뢰 석상, 과부하 도전, 수 약점 보스 |

## 직접 확인할 조작

- WASD / Shift / Space: 걷기·달리기·점프. 절벽에서 E 등반, 공중 Space 활공. 해안·중앙 호수에서 수영.
- 1~4: 기존 4인 파티. 1번 주인공은 고정 멤버.
- Tab: 주인공 원소 전환. G: 기존 원소 스킬 시험. Q: 기존 궁극기 연출. 일반공격은 기존처럼 물리.
- F10 → ↑/↓ → Enter: 같은 섬의 구역으로 빠른 이동. Scene과 플레이어 인스턴스는 그대로이며 체력·스태미나·파티·스킬 대기시간을 유지한다.
- F1 시작 지점 / F2 석상 퍼즐 / F3 도전 입구 / F4 보스 / F5 NPC / F6 조사: **현재 구역 안의** 시험 지점으로 이동한다.
- F: NPC 위임 수락·보상, 상자, 도전 입구, 이동 오벨리스크 상호작용.
- H: 위임·퍼즐·조작법이 포함된 상세 HUD. 기본 HUD는 섬 지도와 파티·체력 중심이다.
- R: 섬 전체 전투·퍼즐 연습 상태 초기화. 보유 재화·위임 기록·주간 보스 처치 기록은 유지한다.

석상은 해당 구역 원소로 I → II → III를 맞힌다. 도전은 F로 시작하고 표적 3개에 표의 원소 반응을 만든다. 주인공이 모든 원소를 사용할 수 있어 파티 로스터를 지역 경계마다 바꾸지 않아도 모든 기믹을 시험할 수 있다.

## 주인공 모델

| 선택 | 참고 원화 | 3D 원본 / 게임 데이터 |
|---|---|---|
| 스텔라 | Assets/Img/여주인공.png | Tools/Blender/Sources/Stella.blend → Island/Models/Stella.fbx → Island/Prefabs/Stella.prefab |
| 폴라리스 | Assets/Img/남주인공.png | Tools/Blender/Sources/Polaris.blend → Island/Models/Polaris.fbx → Island/Prefabs/Polaris.prefab |

`Island/`는 `Assets/Orbis/Game/Island/`를 뜻한다. 최초 제작 스크립트는 `Tools/Blender/create_explorers.py`이며, 현재 얼굴·헤어 개선은 `Tools/Blender/polish_explorers.py`가 담당한다. 원화의 금발, 남색·흰색·금색 의상, 청록색 장식, 나침반과 망토를 참고한 모델에 인물별 얼굴 PNG, 공통 금발 PNG와 새로운 얼굴 UV를 연결했다. 최신 원본·재생성·검증 방법은 [얼굴 개선 안내](Face_얼굴개선_테스트.md)에 있다. 원화와 동일한 고정밀 의상·표정까지 완성한 모델은 아니다. 남녀는 별도 FBX/Avatar를 사용하고, 선택된 쪽만 실제 파티 비주얼로 생성한다.

원소를 바꿔도 모델과 Animator는 그대로다. 기존 Humanoid 애니메이션 7개를 새 Avatar에 리타겟하고 기존 FSM/기본공격/스킬/이펙트 연결을 사용한다. 머리카락·망토는 현재 스킨 메시이며 천 시뮬레이션을 새로 추가하지 않았다. 보스·일반 몬스터·조력자의 원화 모델 교체는 이번 우선 작업에 포함하지 않았다.

실제 사용자 세이브를 지우지 않고 두 선택을 확인하려면 Unity Test Runner의 `Orbis.Game.Tests.ExplorerArtTests`를 실행한다. 두 테스트는 GUID 임시 프로필을 사용해 스텔라·폴라리스를 각각 스폰한다. 일반 Play에서는 저장된 선택을 존중한다.

## 재생성 / 편집

`Create Unified Island`는 기존 씬이 있으면 검증만 한다. 일반적인 편집은 Hierarchy의 저장된 오브젝트와 TerrainData를 직접 수정한다. `Import Explorer Characters`는 두 FBX에서 Humanoid Avatar와 툰 재질·프리팹·카탈로그 연결을 만든다. 모델 생성 원본 .blend는 Unity가 자동으로 Blender 변환을 실행하지 않도록 Assets 밖에 보관한다.

이번 데이터 구조는 기존 지역 ID와 JSON 세이브 포맷을 유지한다. 새 주인공 선택 화면으로 기존 세이브를 덮어쓰거나 재화를 지급하지 않는다. 재시작하면 선택된 주인공으로 자피르 출발 지점에서 시작하며, 마지막 위치 저장 기능은 추가하지 않았다.

## 검증 결과

Unity 6000.6.0f1에서 전체 EditMode 288개와 PlayMode 62개가 모두 통과했다. 결과 XML과 로그는 `TestResults/Island-EditMode.*`, `TestResults/Island-PlayMode.*`에 보존한다.

새 통합 검증은 선택 전 지형 보존, 네 Terrain의 충돌·연속 범위, 한 플레이어로 다섯 구역 전환, F10 입력, 빠른 이동 전후 체력·스태미나·쿨다운 보존, 지역별 퍼즐/도전 기록, 주간 보스 상태, 두 주인공의 Humanoid 걷기·원소 전환·모델 유지 등을 확인한다. 사용자 저장 파일은 사용하지 않는다.

`Island_Overview.png`는 섬 전경, `Island_Player.png`와 지역별 PNG는 실행 중 카메라, `Island_Stella_Unity.png` / `Island_Polaris_Unity.png`는 Unity에서 등장 효과 종료 후 촬영한 모델이다. 캡처용 카메라로 렌더하므로 이 PNG에는 OnGUI HUD가 포함되지 않는다. Blender 정면·얼굴·후면 검토 렌더도 별도로 포함한다.
